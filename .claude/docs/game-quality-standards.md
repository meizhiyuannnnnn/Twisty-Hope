# 游戏质量标准 — 《彼方希冀》

> 每个 Agent 完成工作前，必须对照此文件自检验收。质量不是事后检查，是产出的一部分。

---

## 一、代码质量

### 强制规范

| 标准 | 要求 | 检查方式 |
|------|------|---------|
| **类型注解** | 所有函数签名必须有类型注解（参数 + 返回值） | 人工审查 |
| **Autoload 数量** | ≤ 5 个（当前：EventBus、TimeManager、SaveManager = 3） | 项目设置检查 |
| **通信方式** | 跨系统通信必须通过 EventBus 信号，禁止直接引用 | 代码审查 |
| **继承层级** | ≤ 3 层（基类 → 中间类 → 具体类） | 类结构审查 |
| **`_process` 零分配** | `_process` 和 `_physics_process` 中禁止 `new`、`[]`、`{}` 创建对象 | 代码审查 |
| **信号连接** | 使用 `signal_name.connect(callable)` 语法，不用旧版字符串 | 代码审查 |
| **节点获取** | 使用 `@onready` + `$Path` 或 `get_node()`，禁止 `find_node()` 在 `_ready` 外调用 | 代码审查 |
| **导出变量** | 使用 `@export` 暴露可调参数，不用硬编码常量 | 代码审查 |

### 架构规范

```gdscript
# ✅ 正确：通过 EventBus 信号通信
func take_damage(amount: int) -> void:
    health -= amount
    EventBus.health_changed.emit(character_id, health, max_health)
    if health <= 0:
        EventBus.character_died.emit(character_id)

# ❌ 错误：直接引用其他系统
func take_damage(amount: int) -> void:
    health -= amount
    get_node("/root/UI").update_health(health)  # 紧耦合
```

### 禁止模式

- `call_deferred` 滥用（只在确实需要延迟到下一帧时使用）
- `_process` 中做字符串拼接或数组创建
- 全局变量（用 Autoload 单例代替）
- 超过 500 行的单文件脚本（拆分）

## 二、视觉质量

### 像素美术标准

| 标准 | 要求 | 理由 |
|------|------|------|
| **原生分辨率** | 640×360 | 目标输出 2560×1440（4× 整数缩放） |
| **像素对齐** | 所有精灵使用 `texture_filter = Nearest` | 避免模糊 |
| **调色板** | ≤ 32 色（建议统一调色板） | 保持风格一致 |
| **色彩对比** | 冷暖对比明确（冰雪蓝灰 vs 蒸汽暖橙） | 核心视觉主题 |
| **视差层数** | ≥ 3 层（当前 5 层：sky/far/mid/near/ground） | 深度感 |
| **动画帧率** | 角色动画 8-12 fps，环境动画 6-8 fps | 像素动画标准 |

### UI 一致性

- 字体：统一使用像素字体（建议 DinaRNN 或类似）
- 字号：标题 16px、正文 8px、提示 6px（原生分辨率下）
- 面板样式：统一边框粗细（1px）、背景透明度（80%）
- 图标尺寸：统一 16×16 或 8×8

## 三、游戏手感

### 响应性

| 标准 | 要求 | 理由 |
|------|------|------|
| **输入延迟** | ≤ 2 帧（33ms @ 60fps） | 玩家操作即时反馈 |
| **变速平滑** | 1×/2×/4× 切换无卡顿，过渡时间 ≤ 0.2s | 时间控制体验 |
| **UI 响应** | 按钮点击 → 反馈 ≤ 1 帧 | 交互流畅 |
| **场景切换** | 无加载画面（流式加载或预加载） | 沉浸感 |

### 火车移动

- 加速度曲线：平滑加减速，不是线性变化
- 停止时：轻微惯性滑动，不是急停
- 背景滚动：与火车速度同步，视差层速度递减

### 事件节奏

- 随机事件间隔：3-8 分钟（避免过于频繁或稀疏）
- 紧急事件（火灾、袭击）：立即触发，有音效提示
- 日常事件（对话、发现物品）：可延迟，不打断关键操作

## 四、数据完整性

### JSON 数据规范

| 标准 | 要求 | 检查方式 |
|------|------|---------|
| **Schema 验证** | 所有 JSON 数据文件必须有对应的 schema 定义 | 启动时验证 |
| **事件引用** | 事件 ID 必须全局唯一，引用不悬空 | 启动时扫描 |
| **资源引用** | 资源 ID 必须存在定义，数量 ≥ 0 | 启动时扫描 |
| **车厢定义** | 车厢类型必须有完整的属性（容量、效果、消耗） | 启动时扫描 |
| **角色定义** | 角色必须有完整的属性（技能、需求、状态） | 启动时扫描 |

### 存档系统（待实现）

- 存档不丢数据：所有游戏状态可序列化
- 存档兼容：版本升级时自动迁移旧存档
- 存档不卡顿：保存/加载在后台线程，不阻塞主线程
- 存档有备份：每次保存前备份上一次存档

## 五、性能

### 帧预算

| 标准 | 要求 | 理由 |
|------|------|------|
| **目标帧率** | 60 fps | 流畅体验 |
| **帧预算** | ≤ 16.67ms | 60fps 的硬限制 |
| **DrawCall** | ≤ 50 | Godot 2D 性能关键指标 |
| **内存占用** | ≤ 512 MB | 目标平台（PC）合理范围 |
| **加载时间** | ≤ 3s（首次启动）、≤ 1s（场景切换） | 玩家耐心 |

### 优化红线

- `_process` 中禁止：
  - 创建对象（`new`、`[]`、`{}`）
  - 字符串拼接（用 `StringName` 或预分配）
  - 大量节点遍历（用信号或预缓存引用）
- 粒子系统：总数 ≤ 200 个活跃粒子
- 精灵图集：单个纹理 ≤ 2048×2048
- 音频：同时播放 ≤ 8 个音效

## 六、Agent 产出验收清单

**每个 Agent 完成工作前，必须自问以下 6 个问题：**

1. **代码质量**：我的代码符合类型注解、信号通信、零分配 `_process` 的要求吗？
2. **视觉一致**：我的改动与现有像素风格、色彩对比、分辨率一致吗？
3. **手感影响**：我的改动会影响输入响应、变速平滑、事件节奏吗？
4. **数据安全**：我的改动会破坏 JSON schema、事件引用、存档兼容性吗？
5. **性能影响**：我的改动会增加 `_process` 负担、DrawCall、内存占用吗？
6. **可玩验证**：我的改动可以在 Godot 中实际运行并验证效果吗？

**任何一项答案为"否"或"不确定"，必须修正后才能提交。**

```
Agent 完成工作
    ↓
Claude 对照本文件逐项检查（代码审查 + 视觉审查 + 性能审查）
```
